# Skill: 代码审查 (skill-code-review)

> 来源：03_coding_standards + 06_engineering

## 触发条件

用户说 "review" / "审查" / "检查代码" / "代码审查"，或写完代码后。

## 审查清单

### 1. 代码质量
- [ ] 函数 ≤80 行，单一职责
- [ ] 无重复代码（DRY）
- [ ] 命名见名知意，无 a/b/c/tmp
- [ ] 文件头含版本号、作者、创建时间
- [ ] 每个函数有 Docstring

### 2. 安全性
- [ ] 无硬编码密钥/密码/Token
- [ ] 数据库使用参数化查询
- [ ] 外部输入已校验
- [ ] 文件路径无路径穿越风险

### 3. 健壮性
- [ ] IO/网络操作有异常捕获
- [ ] 边界情况已处理（空值/空文件/除零）
- [ ] 资源正确释放（文件关闭/连接归还）

### 4. 性能
- [ ] 大数据不一次性加载
- [ ] 循环内无频繁 IO/重复计算
- [ ] 无不必要的全局变量

## 执行步骤

```
[DO] 1. 读取目标文件
[DO] 2. 按清单逐项审查
[DO] 3. 列出问题 + 建议修复方案
[DO] 4. 标注严重程度: [必须修复] / [建议优化] / [可选]
```

## 输出格式

```
问题: <问题描述>
严重度: [必须修复 / 建议优化 / 可选]
文件: <文件路径>:<行号>
建议: <修复方案>
```
